# v0.3.0: The live view editor (beta)

A wallpaper-style live backdrop built on OpenRCT2's title screen. This release rebuilds the
screensaver mode's view editor: views are now set directly on the playing park, with a map of
every view, and edits reach the playlist files without an install. The editor is a beta.

## Downloads

- **Windows x64** (`openrct2-v0.5.6-openrct2-screensaver-x64-release.zip`): the patched
  `openrct2.exe` and `openrct2.com` (OpenRCT2 v0.5.6 with patches 0001-0016). Replace both files
  in an OpenRCT2 v0.5.6 install, keeping a copy of the stock pair.
- **Linux x64, beta** (`openrct2-v0.5.6-openrct2-screensaver-linux-x64-beta.AppImage`): a whole
  patched OpenRCT2 v0.5.6 with its own libraries, for any current distribution. See README,
  "Installing" → "Linux".
- **Plugin and generator**: in the source archive (`Settings.cmd` on Windows, `./settings.sh` on
  Linux and macOS; Python 3.11+, no packages).

## The live view editor (beta)

Press E in the screensaver mode, or the bar's Edit views button. The editor has three panes:

- **Views, top left.** The park (hold the name to jump to another park; click it to see the
  playlist's park order and drag parks into a new order) and its views, dragged by their grips to
  reorder them. Timed event views (cut-ins on the park's clock, train cues, shows) are listed apart
  under the route, with when they play next.
- **Toolbox, bottom left.** Frame or Map, add, set to camera and delete a view, rotate and zoom,
  the selected view's hold and pan, undo and redo (Ctrl+Z, Ctrl+Y), Reset view, Play, and a pin
  that keeps the panes on screen. Every button's tooltip names its key.
- **Restore points and Playlist, top right.** Go back to the views as they were when the editor
  opened, at a checkpoint you saved, at the last install, or as generated. The Playlist section
  sets the playlist-wide motion (inertia, when angle and zoom change), timing holds, title music
  and titles; Save keeps them.

Two ways to edit:

- **Frame** (the default): the selected view is the camera. Drag the park to move the shot, and
  the mouse wheel zooms it. What you see is what plays. A view's height is set by itself from what
  is at the screen's centre, so turns pivot on it.
- **Map** (M): the camera steps out and every view of the park shows as a numbered box, with
  dotted lines for the pans (yellow) and cuts (cyan) between them. Drag a box to move its view,
  drag its corner to change its zoom, right-click empty park to add a view there, double-click a
  box to frame it. Event views are locked unless you unlock them (L), as their timing comes from
  the park.

**Edits reach your playlist without an install.** Every save also writes a live file,
`screensaver/live/<playlist name>.json` in OpenRCT2's user folder. Every build applies it, and
"Bake into playlist" on the settings page (or `python tools/bakelive.py`) writes it into the
playlist files (views into the views file, properties and park order into the TOML, comments kept),
with the game still open. Install still works as before.

### Known gaps

- Copy and Paste views, and the Playlist section's Import and Export, are grayed out: they come in
  a later release.
- The live editor still needs the generator for building and installing a playlist. Running the
  editor on its own, with the game starting the build, is planned.
- Moving boxes on the map redraws the whole window; on a slow machine or a very large park the
  frame rate can drop while you drag.
- Editing happens in the screensaver mode of the patched engine. On the stock engine the older
  editor window stays, without the map, live file or restore points.
- Undo history lasts while the game runs; checkpoints are kept (ten per park).

Report problems on the repository's issue page; the beta label comes off once the editor has had
wider use.

## Upgrading

Replace the engine (Windows: the two executables; Linux: the AppImage), download the source
archive and replace your copy of the tools (or `git pull`), then run Install again on the settings
page. Views set in the editor are kept.
