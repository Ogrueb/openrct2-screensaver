# v0.4.0: Playlists made in the game, and a park gallery

A wallpaper-style live backdrop built on OpenRCT2's title screen. This release lets the screensaver mode
do everything on its own: make a playlist from a folder of parks, add parks from a gallery with
pictures, set the generator's options, build and play without leaving the game, and carry playlists to
another computer. It moves to OpenRCT2 v0.5.7. The settings page in the browser becomes a legacy tool.

## Downloads

- **Windows x64** (`openrct2-v0.5.7-openrct2-screensaver-x64-release.zip`): the patched `openrct2.exe`
  and `openrct2.com` (OpenRCT2 v0.5.7 with patches 0001-0024) and a `data` folder with the screensaver's
  plugin, its generator and a Python to run it. Extract it into an OpenRCT2 **v0.5.7** install (download
  the stock v0.5.7 from openrct2.io first if you are on v0.5.6), keeping a copy of the stock pair of
  executables: both executables are replaced, and `data` merges into the install's own (it only adds
  `data\plugin\` and `data\screensaver\`). Nothing else needs installing.
- **Linux x64, beta** (`openrct2-v0.5.7-openrct2-screensaver-linux-x64-beta.AppImage`): a whole patched
  OpenRCT2 v0.5.7 with its own libraries, for any current distribution. Builds from the game run the
  generator with the system's Python (3.11 or newer). See README, "Installing" → "Linux".
- **Source archive**: the tools for the command line and the legacy settings page (Python 3.11+, no
  packages). Not needed to play the screensaver on Windows.

## Everything in the game

Start OpenRCT2 and click the Screensaver button on the main menu (or start `openrct2.exe --screensaver`).

- **A first playlist.** With no playlist yet, the mode shows a panel: **New playlist** asks how its views
  are made (motion, view order, variants, ride pans, park times), takes your parks, builds the playlist
  and plays it. **Import playlist** takes a bundle someone exported.
- **Builds from the game.** The editor's Build pane (bottom right, Ctrl+B) rebuilds the playlist and swaps
  it in while the game keeps running: a square per park shows its state, with messages tagged by park.
- **Parks and playlists.** Tick parks on and off, Add park (park downloads, `.park` files, RCT2 saves
  `.sv6`/`.sv4` and loose objects, converted and installed for you), switch between playlists, make a new
  one or duplicate one.
- **Settings.** A Settings foldout (top right) with a Playlist | Park switch holds what applies to any
  views: motion feel, holds, titles, music, park scripts and event views, and per park its scripts, event
  views, return pan and pan speed. Park settings go into the park's profile at the next build.
- **Event settings.** The Events list under a park's route has a row per animation spot and show: on or
  off, its hold, the show's pan share.
- **Copy and Paste views** (Ctrl+C, Ctrl+V) between parks, or to and from the drawing page, and
  **Import and Export playlist** through the system's file dialog, as promised in v0.3.0's notes. A
  bundle carries the playlist, its views and edits, its parks and your own park profiles.

## The park gallery

Add park and New playlist now open a gallery over the editor: every park in your gallery folders as a tile
with a picture, filters (not in the playlist yet, park size S/M/L, has scripts, has event views), sorting
by name, date or size, and a slider for 1-7 tiles per row. Click parks to pick them in order, then add
them and build, or make a playlist of them. The park behind pauses while the gallery is open. "Browse for
a file…" still opens the system dialog. The same gallery works in the game's own Load window: a Grid view
in its menu (the ▼ beside the column headers), a Gallery button, and folders you add there. The pictures
are the engine's own renders of each park's built area, made once per park in the background (each can
cost the playing park a few frames) and then cached.

## Other changes

- OpenRCT2 v0.5.7. The patches moved over from v0.5.6 unchanged.
- The settings page (`Settings.cmd`, `./settings.sh`) is a legacy tool: it keeps working, labeled so,
  without new features. It still covers macOS, the stock engine, renders, show camera paths and backups.
  The standalone `.exe` builds of it are dropped, as the engine download now runs the generator itself.

### Known gaps

- The editor keeps its beta label. Moving boxes on the map still redraws the whole window, which can drop
  frames on a slow machine or a very large park.
- A park whose scripts are added to a playing playlist starts its script only after a restart of the game
  (the editor says so).
- The gallery has no search. On Linux, the gallery and the new editor features have had no test pass on a
  desktop.

Report problems on the repository's issue page.

## Upgrading

1. Upgrade OpenRCT2 to the stock v0.5.7 release. The patched executables must match the install's
   release: earlier releases' builds are for v0.5.6, this one is for v0.5.7.
2. Extract the new engine build over it (Windows) or replace the AppImage (Linux).
3. If you installed earlier releases with the settings page or `--install`, either run Install again from
   the new source archive, or delete `Documents\OpenRCT2\plugin\rct-screensaver.js` once so the game plays the
   plugin the engine build carries. Views set in the editor are kept.
