# v0.2.1: Older saves and import fixes

A wallpaper-style live backdrop built on OpenRCT2's title screen. This release fixes park
importing on the settings page, so folders of RCT1 and RCT2 saves come in whole.

## Downloads

- **Windows x64** (`openrct2-v0.5.6-openrct2-screensaver-x64-release.zip`): the patched
  `openrct2.exe` and `openrct2.com` (OpenRCT2 v0.5.6 with patches 0001-0015), unchanged from
  v0.2.0. Replace both files in an OpenRCT2 v0.5.6 install, keeping a copy of the stock pair.
- **Linux x64, beta** (`openrct2-v0.5.6-openrct2-screensaver-linux-x64-beta.AppImage`): a whole
  patched OpenRCT2 v0.5.6 with its own libraries, for any current distribution. See README,
  "Installing" → "Linux".
- **Plugin and generator**: in the source archive (`Settings.cmd` on Windows, `./settings.sh` on
  Linux and macOS; Python 3.11+, no packages).

## Fixes

- Import: a folder of loose saves (an RCT1 or RCT2 `Parks` folder, say) was read as one download,
  so only its newest save was imported. Each save is now its own park. RCT1 saves and scenarios
  (`.sv4`, `.sc4`) convert like RCT2 ones (`.sv6`, `.sc6`), through OpenRCT2's converter.
- Import: a save that fails to convert because it uses custom objects you don't have now lists
  every missing object, not just the last two.
- Settings page: the footer links to this repository.
- Linux AppImage: no longer carries the engine's static library (30 MB unpacked it never used).

## Upgrading

Download the source archive and replace your copy of the tools (or `git pull`). The engine is
the same as v0.2.0: on Linux, take the new AppImage for its smaller size; on Windows, nothing to
replace. Run Install again on the settings page; views set in the editor are kept.
